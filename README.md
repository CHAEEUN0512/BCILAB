# 🧊 Fridge Keeper — 냉장고 재고 정리 앱

**냉장고 사진을 찍으면 칸 구조를 알아서 파악하는 것**이 앱 사용의 시작입니다.
지금 사진을 찍을 수 없다면 **블럭 쌓기**로 내 냉장고를 직접 모델링할 수 있습니다.

빌드 도구 없이 `index.html`만 열면 동작하는 정적 웹앱입니다. (GitHub Pages 그대로 배포 가능)

---

## 사용 흐름

### 1. 사진으로 시작하기 📷 — 구역별 한 장씩
냉장고 한 대는 사진 한 장에 다 담기지 않습니다. **냉장칸 · 냉장고문 · 냉동칸**을 각각 찍어 하나로 합칩니다.

1. 구역 탭을 고르고 그 구역을 한 장 촬영 (모바일에서는 카메라가 바로 열립니다). 안 찍은 구역은 건너뛰어도 됩니다
2. 앱이 사진을 분석해 **내부 영역 → 칸 경계 → 좌우 칸막이** 순으로 구조를 잡습니다
3. 인식 결과가 사진 위에 가로선으로 표시됩니다. **선을 끌어 위치를 맞추고**, ✕ 로 지우고, `+ 칸 나누기`로 추가
   - 좌우 칸막이도 자동으로 잡습니다. 칸마다 있는 **`좌우 나누기` / `좌우 합치기`** 로 켜고 끄고,
     점선의 ⇔ 손잡이를 끌어 좌우 위치를 옮길 수 있습니다. 이 조정은 경계선을 움직여도 유지됩니다
4. 눕혀 찍혔으면 `↻ 회전` 한 번이면 다시 인식합니다 (휴대폰으로 찍으면 흔한 상황)
5. 오른쪽에서 완성될 냉장고를 확인하고, 칸 이름·종류를 고쳐 시작

합쳐진 모델의 배치는 이렇게 됩니다 — 냉장칸이 위, 냉동칸이 아래, 냉장고문은 **냉장칸 높이까지만** 붙는 오른쪽 세로 띠(냉동칸은 서랍이라 문 포켓이 없습니다). 구역마다 자기 사진이 배경으로 깔립니다.

```
┌───────────┬────┐
│  냉장칸    │ 문 │
├───────────┼────┘
│  냉동칸    │
└───────────┘
```

블럭 빌더에서도 같은 규칙이 적용됩니다 — 스택에 냉동칸 블럭을 넣으면 문 포켓이 그 위까지만 붙습니다.

### 2. 블럭 쌓아 만들기 🧱
사진이 없어도 됩니다. 선반칸·서랍·야채칸·냉동칸·제빙실 블럭을 위에서부터 쌓고,
각 블럭의 **높이**와 **좌우 분할(1~3칸)**, 이름을 조절하면 같은 냉장고 모델이 만들어집니다.
사진으로 만든 모델도 블럭 빌더로 열어 이어서 손볼 수 있습니다.

### 4. 📸 사진으로 칸 채우기 (AI 인식, 선택)
칸을 고르고 `📸 사진으로 이 칸 채우기` → 그 칸을 찍으면 Claude 비전 모델이 품목을 읽어
**후보 목록**을 만들어 줍니다. 각 후보에는 신뢰도(%), 포장에서 실제로 읽은 글자, 추천 소비기한이 붙고,
신뢰도 45% 미만은 기본 해제 상태로 옵니다. 체크한 것만 칸에 담깁니다.
가려져서 못 본 물건 수도 따로 알려주므로 "이건 사진으로 못 잡았다"가 눈에 보입니다.

- API 키 없이도 **샘플 판독 결과 3장**(실제 냉장고 사진 판독 결과)으로 흐름을 그대로 확인할 수 있습니다
- 실제 판독을 쓰려면 `⋯` 메뉴 → **AI 인식 설정**에서 Anthropic API 키를 등록합니다
- ⚠️ 키는 이 브라우저의 localStorage에만 저장되지만, **브라우저에 API 키를 두는 것은 안전한 방식이 아닙니다.**
  본인 기기에서 개인용으로만 쓰고 공용 PC에는 등록하지 마세요. 제대로 쓰려면 키를 서버에 두고 프록시를 거치세요.

### 3. 재고 관리 (직접 입력이 기본)
- 도면에서 **칸을 클릭** → 그 칸에 식재료를 담기 (이름 · 카테고리 · 수량/단위 · 소비기한 · 메모)
- 항목의 **⇄ 버튼**으로 다른 칸에 한 번에 옮기고, 입력·편집 폼의 `담을 칸`으로도 옮길 수 있습니다
- 이름만 적고 넘어가면 **카테고리와 소비기한을 자동으로 제안**합니다 (우유 → 유제품 · D+7)
- 소비기한은 `+3일 / +7일 / +30일` 버튼으로도 빠르게 입력
- 깊숙이 넣어 잊기 쉬운 칸도 도면 위에 개수와 임박 색상이 그대로 보입니다
- 칸마다 보관 개수와 **가장 급한 소비기한 색상(🟢 넉넉 / 🟡 3일 이내 / 🔴 지남)** 이 표시됩니다
- 탭: `선택한 칸` · `소비기한`(7일 이내 임박순) · `전체 목록`, 상단 검색으로 이름·메모·카테고리·칸 이름 검색
- `⋯` 메뉴: 구조 다시 만들기 / JSON 내보내기 · 가져오기 / 전체 초기화

## 사진에서 구조를 읽는 방법

서버도 외부 API도 쓰지 않습니다. 모든 계산은 브라우저의 canvas 픽셀 위에서 이루어지고,
사진은 기기 밖으로 나가지 않습니다. (`js/vision.js`)

| 단계 | 하는 일 |
|---|---|
| 1. 전처리 | 최대 폭 520px로 축소 후 그레이스케일 변환 |
| 2. 내부 영역(ROI) | 행·열별 **밝기 + 엣지 밀도**를 섞은 프로필에서 임계값 이상인 가장 긴 구간을 찾음. 선반 앞면 같은 어두운 띠가 구간을 끊어놓기 때문에 **짧은 끊김(6% 이하)은 이어 붙여** 판단 |
| 3. 선반 라인 | ROI 안에서 각 행의 위·아래 밝기 단차가 임계 이상인 픽셀 비율(= 가로로 얼마나 길게 이어지는가)을 구하고, 비최대 억제 + 최소 간격(7.5%)으로 최대 6개의 봉우리를 선택 |
| 4. 좌우 칸막이 | 선반 사이 구간마다 같은 방식을 세로로 적용. 구간의 55% 이상을 관통하는 세로선만 칸막이로 인정 |
| 5. 모델화 | 라인 사이 구간을 칸으로 변환 — 냉장칸은 선반 1..n(맨 아래는 야채칸으로 추정), 냉동칸은 냉동칸 1..n, 냉장고문은 도어 1..n |
| 6. 구역 합성 | 세 구역의 결과를 한 냉장고 좌표계(냉장칸 위 62% / 냉동칸 아래 38% / 문 오른쪽 띠)로 합쳐 zone 목록 완성 |

신뢰도는 검출된 봉우리의 강도와 개수로 산출해 화면에 %로 보여줍니다.
아무 라인도 잡히지 않는 민무늬 사진이면 4칸 균등 분할을 낮은 신뢰도로 제안하고, 사용자가 끌어서 맞춥니다.

검증: 합성 냉장고 사진(선명/흐릿한 선반, 비네팅, 3° 기울어짐)에서 검출된 라인이 실제 위치 대비 오차 약 1.5% 이내.

## 냉장고가 스스로 촬영해 재고를 갱신하는 건 가능한가

**하드웨어는 이미 상용화되어 있습니다.** 삼성 Family Hub는 내부 카메라로 문이 닫힐 때 촬영해
들고 나는 품목을 인식하고, LG·보쉬 등도 유사한 기능을 냅니다. 어두운 내부 촬영도 큰 장벽이 아닙니다 —
① 문이 열린 상태에서 촬영하거나 ② 촬영 순간만 LED를 점등하거나 ③ 근적외선 조명+IR 센서를 쓰면 됩니다.

진짜 어려운 건 조명이 아니라 다음 네 가지이고, 이 저장소의 샘플 판독 결과가 그대로 보여줍니다.

| 난제 | 샘플에서 확인된 현상 |
|---|---|
| **가림(occlusion)** | 앞줄이 뒷줄을 덮어 도어 포켓 외에는 절반 이상이 보이지 않습니다. 서랍을 닫으면 0%입니다. |
| **불투명 용기** | 흰 반찬통·지퍼백은 "통이 있다"까지만 알 수 있고 내용물은 원리적으로 알 수 없습니다. 샘플 A에서 9개, C에서 14개가 여기 해당합니다. |
| **소비기한 판독** | 날짜 표기는 대부분 뒷면·바닥이거나 가려져 있습니다. 샘플 B의 손글씨 메모처럼 사람만 아는 정보도 많습니다. |
| **성에·반사** | 냉동실(샘플 C)은 성에와 반투명 포장 때문에 신뢰도가 0.25~0.5로 떨어집니다. |

그래서 "카메라 한 대로 전수 재고를 자동 관리"는 아직 무리이고, 현실적인 설계는 **전수 스캔이 아니라 변화 감지 + 사람 확인**입니다.

1. **넣을 때 한 장** — 사용자가 물건을 넣으며 찍으면 그 순간이 가장 잘 보입니다. AI는 후보만 만들고 확정은 사람이 탭 한 번으로 (이 앱이 구현한 방식)
2. **차분 감지** — 문 닫기 전후 사진을 비교해 "들어온 것 / 나간 것"만 잡으면 전수 인식보다 훨씬 쉽습니다
3. **바코드·영수증** — 공산품은 카메라보다 바코드가, 장보기 직후엔 영수증 OCR이 압도적으로 정확합니다
4. **소비기한은 규칙으로** — 품목별 통상 소비기한을 자동 제안하고 사용자가 고치는 편이 라벨 OCR보다 실용적입니다

이 앱은 1번과 4번을 구현했고, 2·3번은 같은 `AI.recognize()` 인터페이스 위에 확장할 수 있게 열어두었습니다.

## 데이터

- 모든 데이터는 브라우저 `localStorage`(`fridge-keeper-v1`)에 저장됩니다
- 사진은 구역별로 인식된 내부 영역만 잘라 JPEG로 축소 저장하며, 용량이 부족하면 사진을 버리고 재고 데이터를 지킵니다
- JSON 내보내기/가져오기로 기기 간 이동 가능
- 구조를 다시 만들어도 **같은 이름의 칸으로 재고를 옮겨** 유지합니다

## 파일 구조

```
index.html          화면 4개(시작 · 사진 스캔 · 블럭 빌더 · 메인)
assets/styles.css
js/store.js         모델·재고 상태와 localStorage 영속화, 소비기한 계산
js/vision.js        사진 → 칸 구조 인식, 구역 합성, 회전 처리
js/blocks.js        블럭 쌓기 빌더
js/render.js        zone 목록 → SVG 냉장고 도면
js/app.js           화면 전환과 전체 흐름
sw.js               오프라인 캐시 (서비스워커)
manifest.webmanifest  홈 화면 설치 정보
```

## 폰에서 쓰기

카메라는 **HTTPS에서만** 열립니다. GitHub Pages로 올리면 폰에서 바로 촬영까지 됩니다.

1. 저장소 **Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)`**
2. 잠시 뒤 `https://<사용자>.github.io/bcilab/` 로 접속
3. 폰 브라우저에서 열고 **홈 화면에 추가**
   - 안드로이드 크롬: 시작 화면의 `📲 홈 화면에 추가` 버튼
   - 아이폰 사파리: **공유 버튼 → 홈 화면에 추가** (iOS에는 설치 프롬프트 API가 없어 안내 문구가 대신 뜹니다)

> **아이폰은 홈 화면에 추가하는 편이 안전합니다.** Safari는 7일간 사이트를 쓰지 않으면
> 스크립트가 쓴 저장소(localStorage 포함)를 지울 수 있는데, 홈 화면 웹앱은 이 제한에서 벗어납니다.
> 어느 기기든 중요한 재고는 `⋯` 메뉴 → JSON 내보내기로 가끔 백업해 두세요.

홈 화면에서 열면 주소창 없이 앱처럼 뜨고(`display: standalone`), **오프라인에서도 열립니다** —
`sw.js`가 앱 파일을 캐시하고(stale-while-revalidate) 재고 데이터는 원래 기기 안에 있기 때문입니다.
주방에서 신호가 약해도 재고 확인·입력이 됩니다. (AI 사진 인식만 네트워크가 필요합니다)

> 앱을 고친 뒤에는 `sw.js`의 `VERSION` 값을 올려야 캐시가 갱신됩니다.

## 로컬 실행

```bash
python3 -m http.server 8000   # 또는 index.html 을 그대로 열기
```
서비스워커는 https 또는 localhost에서만 등록됩니다. `index.html`을 파일로 바로 열면 조용히 건너뜁니다.
